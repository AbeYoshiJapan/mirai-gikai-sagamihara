# 質問・意見の窓 設計

## 目的

トップページで、AI ではなく運営者に、気軽に質問や意見を送れるようにする。
墨田区版（同じソースからの派生）では、日程などの右側に質問用の窓がある。相模原版では、その場所を「運営者が受け取って答える窓」として使う。

窓の上には、だれが対応しているかを書く（既定の文）。

> 質問やご意見を受け付けています。対応は、現在、運営者（相模原市議会議員阿部善博）が行っています。

## 出す場所と条件

- トップページだけに出す。
- サイト設定の「質問フォーム」がオンで、「AI チャット」がオフのときだけ出す（AI チャットの窓と同じ場所を使うため）。
- パソコン：画面の右側に常に出す（AI チャットの窓と同じ幅・位置）。
- スマートフォン：右下に「質問・意見を送る」ボタンを出し、押すと下から窓が開く。

## 窓の中身

| 欄 | 内容 |
|---|---|
| 送るもの | 「質問」か「意見」を選ぶ（初めは「質問」） |
| 本文 | 必須。文字数の上限は議案ページのフォームと同じ |
| 返信先メールアドレス | 任意。公開しない |
| 公開への同意 | 任意。同意がなければ公開できない |

下に、議会への正式な意思表示（請願・陳情）にはならないことの注意書きを出す。送り先・対応者の一文は、窓の上の紹介文で示しているので重ねて出さない。

## データ

- 送られたものは `reader_questions` に入れる（議案には紐づけない：`bill_id` は空）。
- 質問か意見かを見分けるため、列 `kind`（`question` / `opinion`、既定 `question`）を足す。
  - migration：`supabase/migrations/20261109120000_reader_questions_kind.sql`
  - 既存の行と、議案ページ・「よくある質問」ページの質問フォームから届くものは `question` のまま。
- 届いたときの Slack 通知は、意見なら「意見が届きました（未返信）」とする。

## 管理画面

- 「意見・質問」の切り替えを「議案への意見」「質問・窓からの意見」と書き分ける。窓から届いたものは「質問・窓からの意見」に並ぶ。
- 1 件ずつ「質問」「意見」の印を付ける。意見では欄の名前を「返事」、例文を「ご意見ありがとうございます。…」にする。
- 公開の流れは質問と同じ。運営者が返事を書き、投稿者が公開に同意しているものだけを公開できる。
- 公開したものは「よくある質問」の一覧に出る。意見は「意見」「返事」の印で、質問は「Q.」「A.」の印で出す。
- 「PR・広報」の下書きでは、意見への返事を「【いただいた意見にお返事しました】」として作る。

## サイト設定

- 「サイト」に「質問・意見の窓の紹介文」を足す。`{{operator_title}}` `{{operator_name}}` などの差し込みが使える。空なら既定の文を使う。
- 公開サイトは設定をしばらくキャッシュする。項目を足した版を出した直後は、前の版のキャッシュ（新しい項目が無い）が返ることがあるため、読むたびに既定値を足して欠けを埋める（`withSettingsDefaults`）。

## 反映の手順

1. コードを main に入れる（Vercel が公開サイトと管理画面を作り直す）。
2. 手元で `git pull` のあと `npx supabase db push --remote` を実行し、`kind` 列を本番 DB に足す。

列を足す前に窓から送られた場合は、送信に失敗する（窓は出る）。手順 2 を済ませれば送れるようになる。
