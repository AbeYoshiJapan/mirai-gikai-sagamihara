# PR・広報ページ（管理画面）

議会のニュースや、利用者とのやりとりを X（Twitter）で発信する手助けをする。2026-11-09 の運営者の依頼による。

## 方針

- **自動投稿はしない**。下書きを作り、運営者が直して、自分のアカウントで投稿する
  （X の API は有料で、自動投稿は「運営者が確認したものだけ出す」という掲載方針とも合わないため）
- 下書きの材料は**公開中のものだけ**（仮登録・未公開・確認前のものは使わない）
- 利用者の意見は、サイトへの掲載には同意をもらっているが、X での引用までは同意をもらっていないので、
  **投稿者の文は引用しない**（「意見を○件紹介しています」と意見の欄へ案内する）。質問は公開用の要約を使う

## 画面（/pr）

| 欄 | 材料 | 下書きの中身 | リンク先 |
| --- | --- | --- | --- |
| 議会での質問 | 公開中の council_questions（新しい定例会議 2 つ） | 区分ごとの人数、一般質問の日程 | `/council-questions/{定例会議}` |
| 会議の予定 | 公開中の council_meetings（今日から 14 日） | 日付・曜日・開始時刻・会議名・場所・案件 | `/schedule` |
| 議案 | 公開中の議案（更新の新しい順 10 件） | 題名・議案番号、議決済みなら日付と結果 | `/bills/{id}` |
| 皆さんとのやりとり | 公開中の意見（議案ごと 5 件）、公開中の質問と回答（5 件） | 意見の件数 ／ 質問の要約 | 議案のページの意見・質問の欄、または `/questions` |

- 各下書き：文を直せる、X の数え方で文字数を表示（日本語 2・英数字 1・URL 23、上限 280）、コピー、
  「X で投稿する」（`twitter.com/intent/tweet` を開く）、「投稿済みにする」
- 上限を超える下書きは、題名・案件・質問などの 1 行だけを縮めて収める
- ハッシュタグはサイト設定「サイト」→「X のハッシュタグ」（空なら入れない）
- リンク先の URL はサイト設定の本番 URL（空なら環境変数 `NEXT_PUBLIC_WEB_URL`）

## データ

- `pr_post_logs`：投稿したことの記録（話題の種類・ID・投稿した文・日時・記録した管理者）。RLS は既定で全拒否
- DB の更新前でも画面は開け、下書きのコピーと投稿はできる（記録のボタンだけ使えない）

## 公開ページのパス

管理画面から公開ページへのリンクは `@mirai-gikai/shared/public-paths` を使う。web の `routes.ts` と同じ形であることを
`web/src/lib/routes.test.ts` で確かめている。
